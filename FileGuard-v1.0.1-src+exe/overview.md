# FileGuard 交付说明

Windows Server 共享文件夹的**访问监控 + 删除保护 + 一键恢复**工具。Python 实现，单文件 exe 交付，含 tkinter 控制台与 Flask Web 管理界面。

### 变更 11｜回收站恢复后再删除，不再被「彻底删除」

| 项 | 内容 |
|---|---|
| **涉及模块** | `app/recycle.py`（`restore()` 重建 active 基线、`mark_deleted()` 增加兜底、恢复改原子覆盖）、`app/protector.py`（删除事件与存档噪声**分开抑制**、恢复前后抑制时机）、`tools/smoke_test.py` |
| **触发条件** | 从 Web 回收站恢复某文件后，再次删除它 |
| **预期结果** | 再次删除**重新进入回收站**（可恢复 + `files/` 有实体副本），不多记、不重复落副本 |

这里其实是**两个独立缺陷**叠加，实测均复现：

1. **恢复没有重建 active 版本基线**：`restore()` 把记录置为 `state='restored'` 就结束了，
   而恢复后的文件其实已经回到磁盘。此时该路径**没有任何 active 版本**，
   再删除时 `mark_deleted` 只认 `state='active'`，找不到可标记的记录 →
   判定「不可恢复」→ 文件被真删、回收站里什么都没有。
   → 修复：`restore()` 成功后**为还原目标补一条 active 版本**，把「磁盘上的文件 ↔ 一个 active 版本」这条镜像不变式建回来。
   另外 `mark_deleted()` 增加兜底：路径下没有 active 但存在 `restored` 记录（升级前用旧逻辑恢复过的历史数据）时，
   只要内容还在就照样收回回收站，并**清掉 `restored_at` / `restore_target`**（否则记录会被回收站口径过滤掉，等于白删）。
2. **恢复用的抑制窗口把后续删除事件一起吞了**：恢复时会 `_suppress_path(路径, 8~12s)` 压掉自己回写文件产生的
   创建/重命名噪声，但 `on_deleted` 以前也走同一张抑制表 —— 用户在恢复后 8 秒内删该文件，
   删除事件被静默丢弃：没进回收站、也没有删除日志。
   → 修复：删除事件改用**独立的一套短窗口抑制**（只用于恢复覆盖写时内部删旧文件），
   且恢复改为优先 `os.replace` 原子覆盖，不再为了覆盖先删旧文件，从源头上不产生假删除事件。

### 变更 12｜创建 / 修改 / 删除记录都能显示操作者了

| 项 | 内容 |
|---|---|
| **涉及模块** | `app/protector.py`（`on_created` 延后记日志、`_flush_pending_creates`、`flush_create_log`、`_actor_now`）、`app/audit.py`（`actor_info(fresh=)` / `catch_up()` / `set_actor_hook()`）、`app/service.py`（装配两个钩子） |
| **触发条件** | 通过共享访问创建 / 修改 / 删除文件 |
| **预期结果** | 三种操作的「操作者」「客户端 IP」都不再为空 |

实测（真实 SMB + 真实安全事件日志）定位到根因：**安全审计事件比文件系统事件晚到约 1.5 秒**。

- 「创建」记录以前是在 `on_created` 里**立刻**写的（t+0.1s），那一刻 5145 还没进安全日志 →
  一个路径上的**第一条**记录（正是「创建」）永远拿不到操作者；后续「修改/删除」因为缓存已经热了才有名字。
- → 修复：`on_created` 仍然**立即存档**（保证内容安全，删了也能找回），但**不立即记日志**；
  把「创建」记录挂起，等审计拿到该路径的归因后**立刻补写**，
  并且补写发生在采集器写入同一次访问的「读取/写入」行**之前**，所以日志顺序不会倒挂。
  记录使用原始时间戳，`ts` 列依然是准确的创建时刻。
- 另有兜底：`_flush_pending_creates()` 在归因可用时（或最迟 2 秒后）强制补写，
  避免「事件被抑制 / 文件很快被删」导致记录丢失。
- 「修改/删除」若缓存未命中，`_actor_now()` 会**即时催一次采集**（0.8 秒限流），而不是干等。
  这是刻意选择：日志是顺序敏感的追加文件，不能为了等归因把写入推迟（会打乱时间序）。

### 变更 13｜最小化到托盘时图标正确显示

| 项 | 内容 |
|---|---|
| **涉及模块** | `FileGuard.spec`（`datas` 增加 `assets`）、`app/tray.py`（图标加载重写）、`app/gui.py`（窗口/任务栏图标） |
| **触发条件** | 关闭主窗口 / 最小化到系统托盘 |
| **预期结果** | 托盘与任务栏显示 FileGuard 自己的图标，而不是 Windows 默认图标 |

根因：打包配置 `datas` 只带了 `app/static`，**`assets/fileguard.ico` 没进 exe**；
`tray_icon_path()` 在打包态去 `_MEIPASS/assets/` 找 ico，必然找不到 → 退回系统默认图标。

修复：

- `FileGuard.spec` 的 `datas` 增加 `('assets', 'assets')`，ico 随包分发。
- `_load_icon()` 改为三级兜底：随包 ico → **从运行中 exe 内嵌资源 `ExtractIconExW` 取** → 系统默认图标；
  并按系统小图标尺寸（`SM_CXSMICON`）加载，托盘图标不再被 32×32 缩放糊掉。句柄做了缓存，避免泄漏。
- `tray_icon_path()` 额外支持「exe 同目录的 assets/」与源码目录，漏包时用户把 ico 放到 exe 旁边也能生效。
- 主窗口增加 `iconbitmap`，任务栏 / 标题栏图标同步。

## 前次变更：归因修复 + 回收站口径 + 实时刷新 + 读取补全

### 变更 6｜删除记录的操作者与客户端 IP 归因重做（四级归因）

| 项 | 内容 |
|---|---|
| **涉及模块** | `app/audit.py`（`ActorCache` 新增删除事件表、`remember_delete`/`lookup_delete`、`_skip_process` 收窄、模块 docstring）、`app/config.py`（`actor_backfill_ms` 800→2500、`actor_backfill_seconds` 支持 `min_ms`）、`app/protector.py`（`_queue_delete_log` 重写、`_resolve_actor_into`）、`app/service.py`（回填窗口取 `poll+1.5s`） |
| **触发条件** | 任意客户端（或本机）删除监控目录内的文件/目录 |
| **预期结果** | 删除日志与 Web 界面「操作者」「客户端 IP」两列**不再为空**：本机删除显示账号 + `attribution=delete_event`、IP 列显示「本机操作」；网络删除显示真实账号 + 真实客户端 IP |

根因（实测复现）与修法：

- **4663 账号未回灌给删除归因**：原 `ActorCache` 只被 5145 喂。改为新增「删除事件表」——4663 一旦命中删除掩码，立刻 `remember_delete(path, user, ip, …)`，`lookup()` 优先读它（最可靠）。
- **回填窗口短于审计轮询**：原 `actor_backfill_ms=800`，而审计每 2s 轮询一次，删除日志早在 4663 到达前就写死了。改为回填窗口取 `max(actor_backfill_ms=2500, 轮询间隔 + 1500ms)`，默认约 3.5s。
- **内核 SMB 的 4663 被当噪声丢掉**：网络删除时 `ProcessId=0x4`、进程名为空，原 `_skip_process` 把它当系统噪声过滤。改为**只按「PID==自身 或 可执行名==自身」过滤**，空进程名/PID=4 一律放行。

复测：本机删除 → `user=范浩明\Administrator, attribution=delete_event`；网络删除 → 带真实客户端 IP。

### 变更 10｜文件读取记录补全（去重 + 大小写还原 + 回环可记录）

| 项 | 内容 |
|---|---|
| **涉及模块** | `app/audit.py`（`_canon` / `_dedup_ok` / `_ts_epoch` / `_read_ext_ok`、`_handle_5145` / `_handle_4663` 改造、掩码按 `read_extensions` 自动加读权限）、`app/config.py`（`dedup_seconds` / `skip_loopback` / `read_extensions`）、`app/static/index.html`（概览「读取记录」行） |
| **触发条件** | 客户端或本机打开/读取监控目录内的文件 |
| **预期结果** | 一次打开只记一条（原会记成 3~7 条）；路径大小写还原为磁盘真实名；本机回环访问默认可记录；SMB 缓存命中的纯读取可用 `read_extensions` 兜底 |

实现要点：

- **按事件时间去重**：`dedup_seconds`（默认 2s）窗口内，同一 `(路径, 操作, 账号)` 合并；比较基准用**事件自带时间戳**而非处理时刻（一轮询取回数秒事件，用处理时间会误合并相邻真实访问）；5145 命中时优先顶掉同窗的 4663。

- **纯读取兜底**：把 `.xlsx`/`.docx` 等填入 `read_extensions`，会用 4663 记录这些扩展名的读取（SMB 缓存命中时 5145 抓不到的情况），代价是安全日志量增大——默认关闭。

### 变更 5｜新增「多少天自动清理一次」的回收站清理周期配置

| 项 | 内容 |

## 前次变更：三处功能调整

### 变更 1｜删除文件改为「移入回收站」，删除对该客户端正常生效

| 项 | 内容 |
|---|---|
| **涉及模块** | `app/protector.py`（删除处理）、`app/recycle.py`（回收站存储）、`app/config.py`（新增 `on_delete_action`）、Web/GUI 展示 |
| **触发条件** | 监听到监控目录内文件/目录被删除；`protection.on_delete_action = move_to_bin` |
| **预期结果** | 原路径文件**确实消失**（删除对客户端生效，不会"删不掉"），同时该文件内容被复制到回收站可见目录 `files\盘符\相对路径\…`；当天的 `delete_yyyyMMdd.log` 记录 `action=move_to_bin` 与 `bin_path`；Web 界面可一键恢复 |

实现要点：

- 新增可见副本目录 `<回收站>\files\`，**保留原盘符与相对路径结构**，运维不用登录 Web 也能直接翻找被删文件；重名冲突自动加时间戳后缀。
- 新增 `recycle_bin.remove_bin_copy_on_restore`：恢复后是否收回副本；若恢复目标路径与副本路径相同则**自动复用**，不产生重复占用。
- `on_delete_action` 提供三档：`move_to_bin`（默认，移入回收站）/ `restore`（旧行为，立即还原）/ `record`（只记录不处理）。非法值被 `validate()` 拦下。
- **修复 watchdog 把"目录被删"报成"文件被删"**：`_handle_delete` 通过 `count_versions_under` 判定目录/文件，目录删除走 `_handle_dir_delete` 批量移入回收站；目录内文件若已被单文件事件处理过，用 `list_deleted_under` 去重，避免出现"不可恢复"的假记录。

### 变更 2｜关闭窗口不停止服务，「停止服务」是唯一停止入口

| 项 | 内容 |
|---|---|
| **涉及模块** | `app/gui.py`（关闭与托盘逻辑）、`app/tray.py`（**新增**系统托盘）、`app/main.py`（重复运行提示） |
| **触发条件** | 服务运行中点击窗口右上角 ×；或使用托盘菜单 |
| **预期结果** | 窗口**隐藏到系统托盘**，服务继续运行（Web 端口仍可访问、监听仍生效）；托盘菜单「退出界面（服务继续后台运行）」同样只关界面不停服务；**只有点「停止服务」按钮才真正停止** |

实现要点：

- `app/tray.py` 纯 ctypes 实现 `Shell_NotifyIconW` + 隐藏消息窗口 + `WM_TRAY` 回调，右键弹出菜单：**「显示主界面」/「打开 Web 界面」/「退出界面（服务继续后台运行）」**——菜单里**没有**"停止服务"项，从设计上杜绝误关。
- 首次隐藏到托盘弹一次气泡提示，告知程序仍在后台运行。
- 服务处于停止状态时关闭窗口才是真正退出程序（`_really_exit`）。
- 托盘动作在 tkinter 线程消费（`_tick` 每 400ms 轮询 `poll()`），**回调里不 sleep**，不阻塞事件循环。
- 踩坑：64 位下 `lParam/WPARAM` 是 64 位，ctypes 默认按 32 位 int 转换会抛 `OverflowError: int too long to convert`；已为所有用到的 `user32/kernel32/shell32` 函数显式声明 `argtypes/restype`。

### 变更 3｜访问记录与删除记录补齐客户端 IP

| 项 | 内容 |
|---|---|
| **涉及模块** | `app/audit.py`（三级归因 + SMB 会话表）、`app/protector.py`（归因窗口）、`app/recycle.py`（记录字段）、`app/web.py`（导出列）、Web 界面 |
| **触发条件** | 采集到 5145（共享访问，自带 IP）或 4663（对象审计，不带 IP）事件；发生删除操作 |

三级归因（`audit.session_lookup = true` 时启用）：

| 级别 | 来源 | `attribution` |
|---|---|---|
| 1 | 路径缓存（同文件最近一次 5145 访问者） | `exact` |
| 2 | 账号缓存（大小写/域名写法不同也命中） | `exact` |
| 3 | SMB 会话表 `NetSessionEnum(10, None)` 按账号匹配 | `exact` |

## 历史变更：配置改为 YAML 格式（含完整注释）

配置文件由 `config.json` 改为 **`config.yaml`**，每一项配置的上方都写明**用途 / 取值范围 / 默认值**。

**为什么注释不会丢**：PyYAML 保存时会把注释一起丢掉，所以注释不是在文件里"维护"的，而是作为**配置项元数据写在代码里**（`app/config.py` 的 `_NODE_DOC`，含 `{default}` 占位符自动取真实默认值）。每次保存都按内置默认结构重新渲染全文，因此：

- 在 Web 界面改完配置保存后，注释自动补回；
- 升级新增配置项时，新项自动出现在用户文件里并自带注释；
- 注释里写的默认值永远和代码一致，不会脱节。

配套改动：

| 位置 | 改动 |
|---|---|
| `app/yamlconf.py` | 新增：YAML 安全加载 + 带注释渲染器（标量转义严格按 YAML 1.1 隐式类型规则，`yes/no/on/off`、纯数字、`2026-09-30` 这类值一律加引号，保证读回来类型不变） |
| `app/config.py` | 40 个配置项的注释元数据；YAML 读写；**旧 `config.json` 自动迁移**（旧值保留、缺项补默认、旧文件改名 `.migrated` 备份）；语法损坏时备份为 `.broken` 并回退默认值启动 |
| Web「系统配置」页 | 改为 YAML 全文编辑器，服务端解析 + 校验，**语法错误提示到具体行列**；保存后回填带注释的规范化文本 |
| 主界面 | 「编辑 config.yaml」用记事本打开（`.yaml` 无系统关联）；新增「配置文件」信息行；迁移时在日志区提示 |

## 两个核心难点的实现方式

**1. 删除文件时数据不真正丢失**

纯 Python 无法拦截内核级删除（那需要文件系统微过滤驱动），因此采用**实时镜像 + 删除后收进回收站**：
文件每次创建/修改都会把内容按 SHA-256 存进回收站（相同内容全盘只存一份）；
监听到删除事件时，删除**照常生效**，但把最新版本复制到回收站可见目录 `files\`（保留原目录结构）。
目录被整体删除时批量处理目录下所有文件。自产生的文件事件被抑制窗口过滤，不会造成循环；
同一路径 10 分钟内被反复删除超过阈值会降级，避免异常客户端导致的死循环。

**2. 识别「哪个客户端 IP 的哪个账号」**

用 Windows 原生安全审计，两条低开销通道：
`auditpol` 开启「详细的文件共享(5145)」拿到**带客户端 IP 的访问记录**，
在共享目录写入一条仅含删除类掩码的 **SACL**，通过「文件系统(4663)」做删除归因；
4663 本身不带 IP，按**删除事件表 → 路径缓存 → 账号缓存 → SMB 会话表**四级归因补上，查不到就留空不瞎猜。
掩码只放 `DELETE | FILE_DELETE_CHILD` 是关键——全量读审计会把繁忙服务器的安全日志瞬间刷爆。

## 关键实现决策

- **注释即元数据**（见上）：不依赖任何能"保留注释"的 YAML 库，避免多一个依赖和 round-trip 兼容性问题。
- **标量转义按隐式类型规则严格处理**：`yes/no/on/off`、`123`、`1e5`、`2026-09-30` 都加引号；`D:\Share`、`0.0.0.0`、`utf-8` 直接裸写，兼顾正确性与可读性。渲染 → `safe_load` → 与原数据全等，有单元测试守着。
- **配置写坏不会让服务起不来**：解析失败时备份 `.broken` 并回退默认值，界面明确提示。
- **日志用 JSONL**（每行一个 JSON）：既能 `tail -f` 直读，也能被程序高效解析与分页；按大小自动轮转。
- **回收站用内容寻址 + SQLite 索引**：blob 按 SHA-256 命名天然去重，索引支持筛选/分页/恢复状态追踪；清理时优先删已删除版本，**绝不删掉每个路径的最新版本**。
- **审计掩码优先按 `AccessMask` 数值判定**：中文系统上 `AccessList` 渲染为 `%%1537` 这类资源号，按文本判断会全部失效。
- **回收站「内容寻址 blob + 可见副本」双轨**：blob 负责去重与版本追踪，`files/` 负责可读可翻找；两者同源，恢复时任选其一。
- **托盘菜单刻意不放"停止服务"**：用"菜单里没有这个选项"从设计层面保证停止入口唯一，比写一堆确认框更可靠。
- **归因宁可留空也不猜**：四级归因全落空时 `ip` 写空字符串，界面显示"未能识别来源"——错 IP 比没 IP 更糟。
- **Web UI 零外部依赖**：单 HTML 文件内联 CSS/JS，服务器无外网也能用；登录默认开启，`web.password` 首次运行随机生成并显示在 GUI 上。
- **exe 内置三种命令行模式**（`--check` / `--selftest` / `--nogui`）：图形程序没有控制台，运维需要一种能拿到结果文件的方式确认部署是否正确。

## 快速上手

## 已知限制（详见 README 第九节）

1. 必须管理员权限（写入 SACL / 读安全日志 / 执行 auditpol）。
2. `protection.strategy = event` 下，创建后毫秒级被删的文件无法保证被存档；要求 100% 可找回请用默认 `mirror`。
3. 镜像策略需要磁盘空间（内容去重后通常远小于原目录），用 `max_size_gb` / `retention_days` 控制。
4. `files/` 可见副本仅对"被删除的文件"额外占一份空间；`remove_bin_copy_on_restore=true` 时恢复后收回，同路径自动复用。
5. `\\127.0.0.1\share` 回环访问**默认可记录**（`audit.skip_loopback: true` 可关闭）；审计不可用时读取记录降级为「仅文件系统变更」。
6. 客户端 IP 四级归因全部落空时留空并在界面提示"未能识别来源"，不会写错 IP。
7. 存档只保留内容与时间戳，不保留 EFS 加密、备用数据流（ADS）与 ACL。
8. SMB 缓存命中导致 5145 拿不到的纯读取，需靠 `audit.read_extensions` 用 4663 兜底（默认关闭，开启后安全日志量增大）。
